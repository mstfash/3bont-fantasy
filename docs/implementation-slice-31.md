# Slice 31 — Reliability verification

Implementation 2026-09-19. No application rules or database migrations changed.

The verification entry points now separate fast public smoke checks from the full authenticated workflow suite. `pnpm test:smoke` visits five public routes in both languages, both themes and desktop/mobile viewports: 40 combinations. It verifies successful responses, page headings, locale/direction, theme, decoded brand assets and horizontal overflow. Additional checks cover protected-page redirects, missing competitions and the readiness contract. Its machine-readable result is saved to `artifacts/verification/public-smoke.json`, including failure status when a run fails.

`pnpm test:e2e` runs the existing browser workflow suite. Main and auxiliary browser pages now fail on crashes, uncaught JavaScript exceptions and same-origin HTTP 5xx responses; expected authorization failures and missing-page responses remain explicitly tested. The admin shell has a real wheel-scroll regression check: content scrolls without moving the sidebar, sidebar navigation scrolls without moving content, the document stays fixed, and Arabic mirrors the layout.

Browser authentication setup respects legitimate server throttling. It retries only explicit 429 responses, waits for the bounded Retry-After window, and stops after three attempts. It does not change rate-limit records or retry uncertain network writes, credential failures or server errors. Four harness tests prove these boundaries. Existing unverified-login and session-revocation assertions remain direct, without retry suppression.

Disposable PostgreSQL coverage now also proves that changed kickoff times, postponements and removed competition assignments hold queued provider collection before another request. Incorrect resource requests, lost worker claims and attempts to spend the correction reserve are rejected before reservation. A crash after reservation retains the uncertain charged attempt, defers early retries, then allows a fresh attempt after the uncertainty window. Integration test cases have a two-minute timeout so a lock regression fails the run rather than waiting indefinitely.

The stronger smoke observer caught two logo HTTP 500 responses during a concurrent local rebuild. Restarting from the completed standalone build passed the full public matrix. `pnpm verify:local` prevents this verification workflow mistake: it checks that port 3100 is free before building, runs strict checks and isolated integrations, starts its own preview, waits for database readiness, runs smoke/E2E serially, and stops that preview afterward. It never stops an existing service. Its server log stays under the ignored private `.local/verification/` directory. Stop the local background worker before invoking it because browser fixtures control gameweek deadlines directly.

This suite uses synthetic football data and local services. It does not establish licensed provider coverage, production capacity, an off-host restore, or zero defects. Those gates remain in the [evidence register](evidence-register.md).

Completed verification: `pnpm verify:local` passed all stages, including 79 application/domain unit cases, four harness cases, nine persistence and 73 application integration cases/subcases, the 40-case public matrix and the full authenticated E2E suite. Its occupied-port refusal and shutdown of its owned preview were also checked. `pnpm test:containers` passed against the unchanged slice-30 runtime images. Cleanup left zero QA competitions, temporary staff grants, QA provider seasons or provider schedules. Machine-readable evidence is in `artifacts/verification/reliability-proof.json`, with the build ID, immutable runtime image IDs and verification transcript digest. The local preview and worker were restored after testing; provider automation remains disabled.
