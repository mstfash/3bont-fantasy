# Slice 30 — Scheduled match-source collection

Implementation 2026-09-19, migration `0022-provider-schedules`.

Global data staff can review and save an Arabic/English collection schedule for a bound season. Defaults request sources from one hour before kickoff, every 15 minutes through eight hours afterward, then every six hours through hour 72. Both intervals and the bounded windows are configurable; the correction interval cannot be faster than the active interval. Each batch contains four source requests and consumes ordinary quota, including retries. Provider account activation and the worker deployment's separate automation switch are also required. Changes invalidate pending batches from the previous schedule revision.

Planning considers actively mapped real fixtures assigned to at least one published/running/completed fantasy competition. Shared fixtures get one active batch, regardless of how many fantasy competitions use them. Postponed/void fixtures and fixtures outside the collection window are excluded. The desired cadence may be delayed by queue depth and quota; it is not a freshness or availability guarantee.

Batch claims expire. Quota reservation also records the batch/step/attempt link atomically, protecting provenance and crash recovery. If a worker dies after a successful response is recorded, the next worker adopts it instead of fetching that resource again. Unconfirmed attempts remain charged. At most three attempts are allowed per resource; unfinished batches expire ten minutes after their first reservation. The short dispatch lease retains existing gateway semantics: pausing prevents further reservations but cannot undo a request already reserved or sent.

Account and season pauses, changed schedule revisions, retired/remapped fixtures, changed kickoff/scope and quota limits block dispatch. The scheduler cannot spend the protected correction reserve. Native live transport rejects synthetic seasons before quota reservation. Integration/browser verification uses synthetic fixtures/transports only.

The worker records collection activity, completions and holds in its existing health view. It processes at most four bounded dispatch/recovery operations per minute job, with a wall-time guard and existing account pacing. Server automation defaults off. Completed raw bundles still go through the source-bound match draft and explicit eligibility/fact review; this feature neither assigns fantasy rounds nor silently applies provider facts.
