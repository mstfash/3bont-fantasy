# Slice 23 — Provider identity mapping

Implemented 2026-09-19. Migration 0019 adds evidence-backed season bindings, current club/player/fixture mappings and immutable version history. Global data stewards bind exact league/year evidence, review identity targets, retire conflicting mappings and reactivate or correct links. Names never establish identity. Fixture links require the correct mapped home/away clubs; dependent fixture links must be retired before a club link changes. All writes recheck current authority and fresh MFA, serialize identity changes, validate expected revisions and retain idempotent receipts and audit reasons.

The bilingual admin page exposes saved successful responses, scope selection, source IDs, local targets, current revision/state and reviewed retirement. Source-use references are operator attestations, not automated license verification. Player data with multiple club statistics preserves one player identity without inferring a transfer.

Validation: full formatting/lint/strict type/production-build/unit checks pass; disposable PostgreSQL passes nine persistence and 57 application cases/subcases. Identity tests cover successful evidence, scope, duplicate IDs, same-name records, pagination, failed responses, concurrent retries, stale versions, target collisions, relink review, retirement/reactivation, retained history, fixture dependencies and revoked authority. Browser verification passed: season binding, club mapping, retirement, reactivation, retained history and Arabic mobile layout, followed by the full regression through MFA.
