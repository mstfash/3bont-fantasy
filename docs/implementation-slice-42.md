# Slice 42 — production HTTPS and recoverable authentication startup

Production Compose now includes a digest-pinned Caddy proxy. Only the proxy publishes ports; web and PostgreSQL remain internal. The proxy obtains/renews ACME certificates, persists its certificate state, replaces untrusted client forwarding information, bounds request bodies and adds security headers. Access logging remains disabled and runtime logs omit request objects so backend failures do not retain verification/reset tokens or cookies. A read-only release preflight checks private-file permissions, immutable image references, public-origin agreement and database-secret consistency without printing secrets.

The executable container rehearsal found a startup defect: creating Better Auth during an early readiness probe could cache a missing-schema failure, leaving authentication broken after migration even though database health had recovered. Runtime identity initialization now waits for schema readiness, shares one concurrent attempt and clears failed attempts. Health requires successful identity initialization. Auth endpoints return a bounded unavailable response before migration, then work in the same process afterward. All session and staff callers use the same initialization boundary.

The expanded required container test validates the actual production Compose template, exercises GET/POST authentication before migration, then signs in through the production runtime behind Caddy. The isolated production web has no outbound network route. Its test client trusts the generated test CA explicitly; certificate verification is never disabled. It checks HTTP redirection, EN/AR security headers, secure HttpOnly SameSite cookies, authenticated sessions and revocation, cross-origin rejection and a shared sign-in rate limit despite forged forwarding headers. Stopping the backend produces an observable 502 whose logs omit synthetic request tokens and session cookies. Cleanup removes only the rehearsal's containers/networks/private temporary files.

Local verification passed: strict types/lint/build, 113 unit tests and nine harness cases, 151 disposable PostgreSQL cases, 56 public smoke combinations and authenticated Arabic/English E2E. Rebuilt Linux web/worker images passed the expanded container proof. The encrypted recovery drill again preserved 18 published results, replayed the target WAL transaction, excluded later changes and rejected wrong keys/missing WAL. Source-bound evidence is recorded in artifacts/verification/tls-proof.json, container-proof.json and recovery-proof.json. No application database migration is required.

This is local deployment evidence. Public DNS/ACME renewal, real email, off-host backup access and alert delivery, licensed season/valuation data, production-sized capacity and the named staging release rehearsal remain open gates.
