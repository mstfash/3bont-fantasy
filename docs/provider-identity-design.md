# Provider identity bindings

Selected 2026-09-19. Provider IDs are explicit mappings, never inferred from a matching name. Our footballer and club records belong to an internal season; API-Football league IDs persist across seasons, and a player can have statistics for more than one team after a transfer. See the provider's [ID guide](https://www.api-football.com/news/post/how-to-find-ids) and [league/team/player example](https://www.api-football.com/news/post/how-to-get-all-teams-and-players-from-a-league-id).

A season binding associates one internal season with the provider's league ID and four-digit season key. Creation requires a successful stored league-discovery response containing that exact league and year, plus the operator's source-use evidence. External keys and the internal season stay fixed; correcting a wrong season binding requires a separate reviewed migration once data is consumed.

Within a binding, explicit club, footballer and fixture mappings connect external IDs to existing internal entities in that season. A successful stored resource response must contain the source ID and match the bound league/year. Fixture mapping also verifies its mapped home/away clubs. Names are review labels only. Player statistics with multiple club records do not select a new club automatically.

Mappings are versioned. New evidence can refresh an existing mapping; a target change requires a reviewed new version and a reason. Every import must retain the exact mapping version it used. A future mapping change never silently rewrites existing match facts or squad history; those use the factual correction workflow. Retirement preserves the history and releases the active target for a corrected mapping; new imports cannot use retired versions as current identity. A club mapping cannot be retired or relinked while active fixture mappings depend on it: retire those fixture mappings first, then verify their clubs when reactivating them. Reverse uniqueness prevents two active external identities from accidentally claiming the same internal entity in one binding.

Mapping is not provider coverage or licensing validation. The operator's source-use reference is an explicit attestation, and real Egyptian Premier League 2026/27 coverage still needs the required licensed samples. Fetching, pagination, normalization, conflict quarantine and scheduling remain separate components behind the quota gateway.
